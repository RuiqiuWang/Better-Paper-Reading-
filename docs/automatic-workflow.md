# 自动触发科研流程

正常使用直接描述目标，不需要先记技能名。例如：

> 在指定的两张GPU上开始这个新topic的大规模训练，按现有评测方案验证。

agent应自动按[触发表](../skills/research-workflow/references/triggers.md)完成：

```text
确认课题和资产 → 明确评测协议 → 小预算测速与优化
              → 验证并选配置 → 正式训练/推理 → 保存结果与记录
```

已有匹配性能记录时复用；更换输入、模型、环境或硬件时只重测受影响部分。优化没有收益时保留可靠基线，避免无限调优。原请求已经授权完整实验时，试跑通过后继续正式任务，不要求用户逐步提醒。

`research-workflow`是自然语言总入口，统一协调manage/evaluate/optimize。触发表是场景规则的唯一来源；技能名调用仍可用于直接定位某一工具，但不是正常工作流的前提。`research`与`all`安装组合都会安装完整科研链。

只规划、只测速、补录结果、阅读论文或修改技能文档分别按原范围完成，不因此启动大规模任务。安装规则本身也不会启动实验。

实现采用宿主的隐式技能选择和agent执行步骤，已明确允许implicit invocation；不包含全局shell拦截器或后台调度服务。宿主必须加载已安装技能，新会话/刷新后才能使用更新的发现信息。技能描述决定何时被考虑，实际漏触发应作为行为问题修正，而不是让用户每次手动补命令。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)。
