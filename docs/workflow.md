# 课题工作流 / Topic workflow

从用户当前阶段进入，不要求每个任务重做所有步骤。以下命令输入在agent对话中，Claude Code把 `$` 换成 `/`。

## 1. 理解课题

```text
$read-search <课题方向>
$read <重点论文链接>
```

保留相关论文、代码和阅读笔记。已有课题先读取其README与实验记录；明确输入/输出、研究问题、已有baseline和可用数据。

## 2. 建立可查找的工作区

```text
$research-manage 为当前课题建立或补齐目录导航、方法卡和本地Git。
```

维护课题README、CHANGELOG、方法卡及EXPERIMENTS索引。代码默认在/home，环境和运行产物在/data；已有目录先登记，不自动搬迁。[具体管理规则](research-management.md)。

## 3. 从论文确定评测与保存内容

```text
$research-evaluate 核验相关论文与官方评测代码，制定当前课题的评测和记录协议。
```

产出论文依据表、版本化指标协议、固定样本清单和产物计划。注明哪些方法可直接比较、哪些需要分表；指标必须有定义与来源。曲线、表格和日志根据任务决定。[评测指南](evaluation.md)。

## 4. 在具体工程中接入并实验

明确请求将协议接入实际训练/推理代码；先检查已有输出，再验证小样本记录与评分。是否运行训练、使用哪些GPU和计算预算遵从当前授权。技能安装本身不会执行这一步。

每个run绑定代码、数据、环境、配置、协议和样本清单版本。原始指标与展示图分别保存；实验失败或只完成一部分也保留状态和证据。

## 5. 记录结果并继续研究

```text
$research-manage 根据这个run的原始指标更新实验结果、方法卡和变更记录，维护本地提交。
```

EXPERIMENTS中写具体指标及与baseline的可比结论，链接完整run记录。需要改协议时建立新版本，旧实验保留原引用。只有用户明确要求才推送代码/文档；大权重、媒体和数据留在运行目录。

## 两个仓库层次

Better Research仓库存放可复用技能、工具、指南和验证。具体课题仓库存放该课题的代码、协议、方法卡及实验摘要。不要把真实课题的数据、凭据或全部运行日志混入这个技能项目。
