# 文档模板与维护规则

模板只提供结构；替换占位字段，没有依据的值明确写未知。新建时使用下列最小格式，已有文档保留原内容并补齐所需事实。

## 维护时机

| 事件 | 更新位置 |
|---|---|
| 新课题 | 课题 README、CHANGELOG、实验索引；共享根 README 入口 |
| 新方法/方法功能或依赖改变 | 方法卡、课题方法索引、CHANGELOG |
| 数据/权重/环境新增或迁移 | 相关导航和方法卡、CHANGELOG；记录原路径与新路径 |
| 创建实验 | run README、EXPERIMENTS；标明 planned 或实际 running |
| 实验结束/失败/恢复 | run README、EXPERIMENTS、CHANGELOG |
| 补充/核验/更正结果 | run 的指标与证据、EXPERIMENTS、CHANGELOG；重要发现可在方法卡链接 |

同一次事件在 CHANGELOG 只保留简短说明，详细数值以 run 记录及原始指标为准。不要每个 step 更新索引。用户只要求补录历史时，不启动新实验。

## 课题 README.md

```markdown
# <课题名>
目标：<要解决的问题>
更新时间：<YYYY-MM-DD HH:mm，时区>

## 路径导航
| 内容 | 主机与绝对路径 | 用途/版本 | 核验状态 |
|---|---|---|---|
| 自研代码 | <路径> | <用途/commit> | <已检查/未现场核验> |
| 数据 | <路径> | <数据版本/划分> | <状态> |
| 环境 | /data/<account>/envs/<env-id> | <用途> | <已安装/待安装> |
| 实验结果 | <runs 路径> | 逐次运行产物 | <状态> |

## 方法
- [<方法名>](research/methods/<method>.md)：<用途>。

## 实验与历史
- [实验索引](research/EXPERIMENTS.md)
- [变更记录](CHANGELOG.md)

## 当前状态
<已完成、待完成、阻塞；不要把计划写成完成事实>
```

共享 `/data/<topic>/README.md` 只写课题名、权威文档的主机/绝对路径（可加 Git 文档链接）及更新日期，避免复制整份导航造成两份事实。

## research/methods/<method>.md

```markdown
# <方法名>
方法 ID：<method>
用途：<自研/对比方法；解决什么问题>
来源及版本：<仓库/论文/commit；本地改动位置>
代码：<主机与路径>
环境：<实际环境路径；配方路径>
权重：<路径/版本；如有校验摘要则链接>
输入：<数据/划分/协议位置>
结果：<运行结果根目录>

## 使用入口
<准确的训练/推理入口与配置；明确已验证还是示意，命令不含凭据>

## 当前功能与限制
<已实现/已验证/待完成>

## 相关实验
- <run-id>：<验证了什么>，见 <run README 路径>。
```

## research/EXPERIMENTS.md

```markdown
# 实验索引
更新时间：<带时区的时间>

| Run ID | 目的/主要改动 | 方法/版本 | 数据/协议 | 执行/验证状态 | 具体结果 | 证据 |
|---|---|---|---|---|---|---|
| <唯一 ID> | <对比变量> | <方法/commit> | <split/协议 ID> | <completed/pending> | <指标=数值 单位；完成 N/M> | <run README/指标文件> |
```

每个 run 一行，最新在前。未知指标写“未测”，不能写 0。若结果维度太多，保留最相关的数值及范围，把完整表链接到 run。不同协议不能因同名指标挤成一个没有条件的排行榜。失败 run 同样保留。

## runs/<run-id>/README.md

```markdown
# <run-id>
目的/假设：<本次验证什么>
对照/主要变化：<关联 run 或 baseline；无则注明>
方法/代码版本：<method/commit；未提交改动的记录位置>
环境及配方：<路径>
输入数据/划分/协议：<精确版本和清单路径>
初始化权重：<路径/版本>
实际参数：resolved_config.yaml
运行入口：<脚本/命令及主机；不得含秘密>
开始/结束/更新时间：<带时区；未发生则留待定>
执行状态：planned / running / completed / failed / interrupted
结果验证：pending / verified / failed
验证依据：<检查范围、时间、证据路径；未核验如实写明>

## 具体结果
| 指标 | 数值 | 单位/方向 | 数据范围与样本数 | 原始证据 |
|---|---|---|---|---|
| <指标> | <实际值/未测> | <例如 dB，越高越好> | <split；完成 N/预期 M> | <CSV/JSON 路径及可定位行/键> |

## 产物
- 权重/预测：<路径或不适用>
- 曲线/对比图：<路径或未生成>
- 日志：<路径>

## 结论与限制
<观察到了什么，支持什么，不足以证明什么；失败原因或未完成范围>

## 运行事件与更正
- <时间>：<开始/中断/恢复/补评测/指标更正；原因和证据>
```

不要直接把模板中的枚举全部留作实际状态。指标需保留原始精度或注明展示四舍五入；训练 loss 与验证/测试指标分开。多种子结果注明种子数及汇总方式；时间说明是否含加载/预处理及所用硬件。这些是解释现有数值所需条件，不要求重新设计用户评测。

## CHANGELOG.md

```markdown
## <YYYY-MM-DD HH:mm，时区>｜<新增/修改/迁移/实验完成/实验失败/结果更正>
- 原因：<为什么做>
- 变化：<实际做了什么>
- 位置：<相关路径>
- 结果：<具体数值和条件，或失败/部分完成事实>
- 关联：<方法卡/run-id/原始证据>
```

最新事件在前。历史原因未知写未知；发现原记录错误时追加更正并修正当前导航/结果，保留旧值与理由。补录时间和实验实际发生时间分别说明。

## 有限证据示例（仅示意，禁止当作真实实验写入）

用户给出某 run 的 JSON 显示 `completed=12, expected=50, psnr=21.4`，但无协议和原始数组：记录“12/50 的部分输出，PSNR 21.4（来源为该 JSON，聚合口径待核验）”，验证状态 pending；不能记成 50 条完成、不能宣称优于不同测试集的旧结果。若运行已退出，核实退出原因后分别记录执行状态和结果范围。
