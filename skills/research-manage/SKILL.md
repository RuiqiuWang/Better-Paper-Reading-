# Research Manage

让下一个 agent 能快速知道：课题是什么、文件在哪里、每个方法如何使用、做过哪些实验、具体结果和证据是什么，以及何时因为什么发生了变化。

这是文件与文档管理的最小版本。科研技能统一命名为 `research-<action>`；论文阅读继续使用兼容的 `read-*`。无需安装第三方服务或部署后台监控。

## 开始工作

1. 确定用户指向的服务器、账号与课题；先读该课题已有 README，再读相关方法卡和实验记录。多课题时不要混写；不要从本地 Windows 路径推断远程 Linux 状态。
2. 新建或整理布局时读 [目录规则](references/layout.md)。创建/更新文档或记录实验时读 [文档模板与维护规则](references/documents.md)。
3. 沿用现有 Git 仓库与文档。只创建缺失内容、针对性更新已有内容；不重写第三方 baseline 的原 README。不因使用本技能就重命名、搬动或删除已有资产。
4. 按 [本地 Git 规则](references/local-git.md) 自动维护代码/文档仓库：新课题初始化，已有仓库沿用；有意义的更新核对后做本地提交。可使用 `scripts/local_git.py`。不添加远程或推送，除非用户明确要求。

## 固定的默认布局

- 可编辑代码：`/home/<account>/code/<topic>/`。
- 个人实际环境：`/data/<account>/envs/`；环境配方：`/data/<account>/env_specs/`。不要回退到 home 安装大型环境；目标不可写时记录阻塞。
- 共享数据、官方 baseline 资产和基础模型：`/data/<topic>/`。
- 个人运行产物：`/data/<account>/projects/<topic>/runs/<run-id>/`。
- 路径中的账号、课题和方法来自实际任务，不硬编码示例。用户已有明确约定优先；历史布局先记录真实位置与差异，再在获授权的迁移中改动。

## 文档职责

课题 README 是当前导航，CHANGELOG 是历史；`research/methods/<method>.md` 是方法卡；`research/EXPERIMENTS.md` 是实验索引；每个 run 的 README 是该次实验的详细事实与证据。共享数据根 README 仅指向课题入口。

完成本次授权操作后，在同一任务中同步相关文档：路径变化改导航；方法变化改方法卡；每次实验创建、结束、失败、恢复或指标更正改 run 记录和实验索引；重要变化追加历史。已使用本技能的当前任务后续相关操作继续维护，不要求用户每次重复调用。不要仅承诺“之后会更新”，也不暗示会话结束后自动监控。

## 记录实验和结果

- 保存实验目的、比较对象、方法/代码版本、环境、输入数据与划分、初始化权重、实际配置位置、运行入口、开始/结束时间及带时区的更新时间。
- 具体结果写数值、单位、数据范围和样本数，链接原始 CSV/JSON/日志、checkpoint 和图。训练指标和最终评测分开；不同数据/协议结果分开；部分完成明确写 `完成数/预期数`。
- 区分执行状态（planned/running/completed/failed/interrupted）与结果验证（pending/verified/failed）。进程退出不等于结果已验证。`verified` 必须写明检查了什么、证据在哪；不等同论文结论已获证明。
- 用户提供但尚未复核的结果注明来源。找不到数据写“未测/未核验/未知”，不填 0、不编造指标或历史日期。不为补文档擅自跑昂贵评测、修改指标定义或挑选较好结果。
- 结论限制在已有证据范围。只有输入和协议可比才计算提升；记录失败、负结果和限制。数值更正保留旧值、新值、原因与时间，并同步索引，不能静默覆盖历史。
- 运行目录已经包含实际参数或机器可读结果时链接它们，避免手工复制所有参数。文档不能替代原始结果文件。

## 更新完成前

核对新增链接/路径和证据能否读取；远程不可达时标注“路径来自记录，未现场核验”。记录实际完成、部分完成和待办；只写有意义的变更，不把每个训练 step 写入 CHANGELOG。不把凭据、私钥或带 token 的命令复制进文档。

修改共享目录遵守其现有权限，活动 run 不移动。任何迁移/清理遵循当前用户授权，不从“记录实验”推断运行、删除或扩大共享的授权。记录并发变更时先重读文件，合并他人新增记录；遇到同 run ID 冲突保留证据并澄清，不覆盖另一个实验。

同步实验索引和变更记录后，检查 diff 并提交本任务相关代码/小型文档；凭据、大权重、数据和视频不进 Git。作者身份或暂存区冲突导致无法提交时保留现场并说明。

最终简短说明更新了哪些文档、记录了哪些实验/数值、本地 commit 和哪些内容仍未核验。一次推进用户当前需要的小步，不自动扩展成服务器治理工程。
