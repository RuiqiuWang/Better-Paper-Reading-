# 科研自动触发表

按任务含义和已有状态匹配，不做机械关键词判断。“topic”“大规模”“优化”等词出现在讨论/引用中不等于运行授权。先应用用户范围限制，再选择主场景；多个场景命中时合并所需步骤，每阶段最多执行一次，已有适用证据可以复用。

| ID | 遇到的情况（自然语言例子） | 自动调用与顺序 | 什么时候继续正式运行 |
|---|---|---|---|
| R01 | 新topic/复现方法，并要求完整实验：“在这两张卡上做这个新课题的训练和验证” | manage确认资产/入口 → evaluate补齐相关论文和质量协议 → optimize小预算诊断/试跑 → 正式运行 → manage记录 | 入口与协议就绪，试跑正确、配置可用，设备/规模在授权内 |
| R02 | 已有topic要大规模训练、批量推理或扩大任务量：“用这个模型把整个数据集推理完” | 查管理/协议/性能记录 → 复用或补齐evaluate → optimize检查适用性/必要小测 → 正式运行 → manage | 有匹配的有效配置即可继续；不要求每次重新扫描参数 |
| R03 | 换模型、输入分辨率/时序、精度、环境、服务器或GPU：“换到新机器继续跑” | manage更新实际位置/版本 → evaluate检查质量条件变化 → optimize重测受影响阶段 → 继续原运行目标 | 新条件验证通过；不能沿用旧硬件的速度结论或未核验配置 |
| R04 | 明确的性能问题：“训练等数据”“GPU利用率低”“视频推理很慢” | optimize测原路径和主要瓶颈 → 小预算比较/正确性 → manage记录配置与收益 | 原请求还包含完整实验时继续；若只要求测速/优化，交付该范围后结束 |
| R05 | 恢复/继续中断实验：“接着上次跑，别重做已完成的” | manage读取作业/恢复点/预算 → 检查协议与性能记录是否仍适用 → 必要定向核验 → 续跑 → manage | 无重复活跃作业，恢复点/数据位置/配置有效；同条件不全套重测 |
| R06 | 实验结束、失败或需要补录：“把这次结果整理一下” | manage核对原始产物并登记状态/数值；指标解释需要时evaluate | 补录本身不触发新的训练/推理；失败记录不自动授权重跑 |
| R07 | 新topic只要规划、评测设计或方案：“先想好怎么做，暂时别跑” | 必要的manage/evaluate/optimize文档与静态检查，标明尚未实测 | 到用户要求执行且条件具备时再启动；不得以小测试跑绕过“别跑” |
| R08 | 只读论文、一般解释、修改本技能仓库/README | 对应阅读/开发流程；不启动科研实验链 | 不因文档里出现训练或GPU字样而运行实验 |

“大规模”按成本与风险判断：长时间训练、整库推理、多卡扩容或昂贵批处理都适用，不能只凭固定视频数量。即使用户没说“先优化”，R01/R02/R03仍在正式执行前安排适用的小测；已有匹配证据时只补变化项。

## 数据类型的二级路由

| 条件 | optimize自动加载的方案 |
|---|---|
| 任意陌生领域 | 领域画像、瓶颈诊断和小预算流程 |
| 视频训练/视频推理 | 通用视频输入、时序、传输、计算、输出；区分训练与推理 |
| 两阶段2Dto3D：深度/几何→目标视角生成补全 | 通用视频＋两阶段2Dto3D方案；确认单目、缓存或右目辅助协议 |
| 无相符的专用领域方案 | 从真实入口和官方实现建立课题适配记录，不套用2Dto3D参数 |

二级方案的内容以research-optimize为准，不在本表复制其参数。小预算、正确性、计时口径和停止条件同样由它维护。

## 触发表如何维护

- 出现漏触发、误触发、重复调优或漏掉正式续跑时，记录具体用户请求与课题现状，修改对应行和workflow描述；不要用无限增长的关键词列表替代语义范围。
- 新技能加入时注明触发条件、输入证据、执行顺序、退出/续跑条件，并确保安装profile包含所引用技能。
- 更新后至少复核：新topic全流程、已有配置直接复用、配置变化定向重测、只测速结束、恢复不重复作业、只规划/补录/改文档不运行。安装/链接检查不能代替宿主隐式选择的真实行为验证。
